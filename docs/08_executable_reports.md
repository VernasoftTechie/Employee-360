# Employee-360 — Executable Reports (Doc 08)

**Status:** DRAFT — awaiting approval (batch a).

Three ABAP report programs + one shared engine class, per Rulebook §5:
OO only; inline declarations, `VALUE`/`REDUCE`/`CORRESPONDING`/`FILTER`;
**no** header lines, `OCCURS`, `TABLES`, `SELECT` inside `LOOP`, or native SQL.
All read through the `ZI_HR360_*` CDS views (single set-based reads).

---

## 1. Objects

| Object | Type | Role |
|---|---|---|
| `ZIF_HR360_REPORT_ENGINE` | interface | contract for data retrieval + output building |
| `ZCL_HR360_REPORT_ENGINE` | class | implements the interface; all business logic; unit-tested |
| `ZCL_HR360_ORG_READER` | class | OM traversal (org-unit → employee list, manager chains) — shared with the BO |
| `ZHR360_R_EMP_MASTER_EXPORT` | report | Employee Master Export |
| `ZHR360_R_MISSING_DATA` | report | Missing Data Validation |
| `ZHR360_R_HR_AUDIT` | report | HR Audit Report |
| `ZCL_HR360_REPORT_ENGINE_TEST` | test class | ABAP Unit for the engine |
| `ZMSG_HR360` | message class | all report messages |
| `ZHR360` | BAL log object (SLG0, manual) | run logging |

The three reports are **thin**: parse selection screen → call the engine → hand
the result to `CL_SALV_TABLE` (foreground) or spool/file (background).

## 3. `ZIF_HR360_REPORT_ENGINE`

```abap
INTERFACE zif_hr360_report_engine PUBLIC.

  TYPES: BEGIN OF ty_scope,
           pernr    TYPE RANGE OF pernr_d,
           bukrs    TYPE RANGE OF bukrs,
           werks    TYPE RANGE OF persa,
           orgeh    TYPE RANGE OF orgeh,
           key_date TYPE datum,
           active_only TYPE abap_bool,
         END OF ty_scope.

  METHODS get_employee_master
    IMPORTING is_scope TYPE ty_scope
    RETURNING VALUE(rt_data) TYPE ztt_hr360_emp_master.   " flat export structure

  METHODS get_missing_data
    IMPORTING is_scope TYPE ty_scope
    RETURNING VALUE(rt_data) TYPE ztt_hr360_issue_row.

  METHODS get_audit_summary
    IMPORTING is_scope TYPE ty_scope
    RETURNING VALUE(rs_summary) TYPE zs_hr360_audit_summary.

  METHODS get_audit_detail
    IMPORTING is_scope TYPE ty_scope
    RETURNING VALUE(rt_data) TYPE ztt_hr360_audit_row.

ENDINTERFACE.
```

> Return types (`ZTT_*` / `ZS_*`) are **ABAP dictionary types generated by ADT
> from the CDS views** (`CDS entity → structure`) or local types — no transparent
> tables. If DDIC structures are needed for the ALV field catalog they are
> created as structures (allowed — not "custom tables"); **CONFIRM 13** covers
> whether even structures should be avoided (default: structures OK, they hold
> no data).

## 4. `ZCL_HR360_REPORT_ENGINE` — logic sketch

```abap
METHOD zif_hr360_report_engine~get_employee_master.
  SELECT FROM zi_hr360_employee AS e
    LEFT OUTER JOIN zi_hr360_personal   AS p ON p~EmployeeID = e~EmployeeID
    LEFT OUTER JOIN zi_hr360_orgassign  AS o ON o~EmployeeID = e~EmployeeID
    FIELDS e~EmployeeID, e~FormattedName, e~DateOfBirth, e~Gender,
           e~HireDate, e~CompanyCode, o~OrgUnitName, o~PositionName,
           o~CostCenter, p~EmailAddress, p~MobileNumber,
           e~QualityStatus, e~CompletenessPercent
    WHERE e~CompanyCode   IN @is_scope-bukrs
      AND e~PersonnelArea IN @is_scope-werks
      AND e~OrgUnit       IN @is_scope-orgeh
      AND e~EmployeeID    IN @is_scope-pernr
      AND ( @is_scope-active_only = @abap_false OR e~EmploymentStatus = '3' )
    INTO CORRESPONDING FIELDS OF TABLE @rt_data.
ENDMETHOD.

METHOD zif_hr360_report_engine~get_missing_data.
  SELECT FROM zi_hr360_issue AS i
    INNER JOIN zi_hr360_emp_basic AS b ON b~EmployeeID = i~EmployeeID
    FIELDS i~EmployeeID, b~LastName, b~FirstName, b~OrgUnit,
           i~CheckID, i~Category, i~Severity, i~IssueDescription, i~FieldName
    WHERE b~CompanyCode   IN @is_scope-bukrs
      AND b~PersonnelArea IN @is_scope-werks
      AND b~OrgUnit       IN @is_scope-orgeh
      AND i~EmployeeID    IN @is_scope-pernr
    ORDER BY i~Severity, i~EmployeeID, i~CheckID
    INTO CORRESPONDING FIELDS OF TABLE @rt_data.
ENDMETHOD.

METHOD zif_hr360_report_engine~get_audit_summary.
  SELECT FROM zc_hr360_kpi_overview
    FIELDS SUM( TotalEmployees )        AS total_employees,
           SUM( EmployeesWithIssues )   AS with_issues,
           SUM( CriticalIssueCount )    AS critical,
           SUM( WarningIssueCount )     AS warning,
           AVG( AvgCompletenessPercent ) AS avg_completeness
    WHERE CompanyCode IN @is_scope-bukrs
      AND OrgUnit     IN @is_scope-orgeh
    INTO CORRESPONDING FIELDS OF @rs_summary.
ENDMETHOD.
```

`key_date`: passed to the parameterised twin views (Doc 04 §14) or applied as a
`@Environment.systemField`-free explicit `WHERE` — engine owns the choice, the
reports just pass `p_keydt`.

Constructor optionally takes an injected `zif_hr360_report_engine` /
double for the DB (test seam — PoC pattern).

## 5. Authorization (every report)

```abap
AT SELECTION-SCREEN.
  AUTHORITY-CHECK OBJECT 'P_ORGIN'
    ID 'INFTY' FIELD '0001'
    ID 'AUTHC' FIELD 'R'
    ID 'PERSA' DUMMY ID 'PERSG' DUMMY ID 'PERSK' DUMMY ID 'VDSK1' DUMMY.
  IF sy-subrc <> 0.
    MESSAGE e001(zmsg_hr360).   " 'You are not authorized to display HR data'
  ENDIF.
```

Row-level filtering additionally comes from the CDS DCL (`#CHECK` +
`ZI_HR360_EMPLOYEE_DCL`) — a user only ever sees rows their `P_ORGIN` permits,
in dialog **and** background.

## 6. Output

### 6.1 Foreground — ALV (`CL_SALV_TABLE`)

```abap
cl_salv_table=>factory( IMPORTING r_salv_table = DATA(alv)
                        CHANGING  t_table      = lt_data ).
alv->get_functions( )->set_all( ).
alv->get_columns( )->set_optimize( ).
" title, layout save (variant), zebra, key columns
alv->display( ).
```

`ZHR360_R_MISSING_DATA`: sort by `Severity` (Critical first), colour column via
`set_color` from severity. `ZHR360_R_HR_AUDIT`: two ALVs (summary grid + detail)
via `cl_salv_table` in a splitter, or summary as a header `WRITE` block + detail
ALV.

### 6.2 Background — spool + optional file

- No `p_alv` in batch → engine result written to **spool** as a
  `cl_salv_table` list output (`set_screen_status` / list mode).
- `p_file` → build the file in memory (`VALUE`/`REDUCE` string table), write with
  `OPEN DATASET … FOR OUTPUT IN TEXT MODE ENCODING UTF-8` (app server only; no
  frontend `gui_download` in batch). `p_fmt = 'XLSX'` → `xco_cp_xlsx`
  (in-memory) then `OPEN DATASET` binary.
- Job scheduling: the report is submitted normally via SM36 / `JOB_OPEN` →
  `SUBMIT … TO SAP-SPOOL … VIA JOB` → `JOB_CLOSE`. A convenience
  `SUBMIT`-wrapper is **not** built — standard scheduling is sufficient
  (Rulebook: no gold-plating).

### 6.3 Application Log (`ZHR360`)

```abap
DATA(log) = cl_bali_log=>create_with_header(
  cl_bali_header_setter=>create( object = 'ZHR360' subobject = 'REPORT'
                                 external_id = |{ sy-repid }/{ sy-datum }/{ sy-uzeit }| ) ).
" add: selection summary, row count, runtime, any skipped-source notes
log->add_item( cl_bali_free_text_setter=>create( severity = if_bali_constants=>c_severity_status
                                                 text = |{ lines( lt_data ) } rows selected| ) ).
cl_bali_log_db=>get_instance( )->save_log( log ).
```

Log written in both dialog and batch; viewable in SLG1 under object `ZHR360`.

## 7. Report-by-report spec

### 7.1 `ZHR360_R_EMP_MASTER_EXPORT`

- **Purpose:** full employee master extract for downstream systems / audit.
- **Columns:** EmployeeID, FormattedName, DOB, Gender, HireDate, CompanyCode,
  PersonnelArea, OrgUnit(+Name), Position(+Name), CostCenter, ManagerName,
  Email, Mobile, EmploymentStatus, QualityStatus, CompletenessPercent.
- **Output:** ALV (dialog) / CSV or XLSX to app server (batch).
- **Volume:** one row per employee in scope — set-based single select.

### 7.2 `ZHR360_R_MISSING_DATA`

- **Purpose:** operational worklist of data gaps for HR to fix.
- **Rows:** one per (employee, failed check) from `ZI_HR360_ISSUE`.
- **Grouping/sort:** Severity → OrgUnit → Employee.
- **Extras:** subtotal counts per Severity and per Category in the ALV; the
  same numbers go to the Application Log.

### 7.3 `ZHR360_R_HR_AUDIT`

- **Purpose:** management view — completeness health by org.
- **Summary:** TotalEmployees, EmployeesWithIssues, %WithIssues, CriticalCount,
  WarningCount, AvgCompleteness — from `ZC_HR360_KPI_OVERVIEW`.
- **Detail:** per OrgUnit / PersonnelArea breakdown; optional per-employee list
  when a single OrgUnit is selected.
- **Output:** summary block + detail ALV (dialog); full to spool (batch).

## 8. ABAP Unit — `ZCL_HR360_REPORT_ENGINE_TEST`

`DURATION SHORT`, `RISK LEVEL HARMLESS`. CDS test doubles
(`cl_cds_test_environment` for `ZI_HR360_EMPLOYEE`, `ZI_HR360_ISSUE`,
`ZI_HR360_EMP_BASIC`).

| Test | Asserts |
|---|---|
| `master_scope_filters` | company/orgunit/pernr ranges applied; active-only flag honoured |
| `missing_data_sorted_by_severity` | Critical rows precede Warning; count matches seeded issues |
| `audit_summary_math` | with/without-issue counts + avg completeness correct for a known fixture |
| `file_record_layout_csv` | CSV line = expected field order + separator + UTF-8, trailing newline |
| `no_auth_returns_empty` *(integration-lite)* | with DCL denying, engine returns 0 rows, no dump |

No test touches real PA tables. Target ≥ 80 % coverage on the engine
(Rulebook §2 ATC + test discipline).

## 9. What is intentionally NOT built

- No frontend download in batch, no email delivery, no ALV-to-PDF — not in the
  requirement; add later if asked.
- No custom scheduling UI — SM36 / standard job scheduling.
- No "fix the data" action — this is a read-only/report solution; correction
  happens in PA30 / standard HR tools.
